* 現在のストーリー案の骨格

- 背景 量子ネットワークにおいて忠実度を高いリンクを効率的に判定する手法 LinkSelFiE が提案されている
- 動機 LinkSelFiE は通信需要を考慮していないが、現実には通信需要が高くかつ忠実度の高いリンクの判定が望まれる
- 目的 少ない計測 (バウンス) により利用率 x 忠実度が高いリンクの判定を可能とする


* 現在の問題設定(先生の対話から抜粋)

--- 
Q. LinkSelfie の論文の問題を拡張したい。


ノードS〜ノードD 間のリンク集合 Ｌ だけでなく、

ノードS〜ノードD_n間のリンク集合 L_n (1 <= n <= N, N はノードSの隣接ノード数)がそれぞれ入力される。

ノードS〜ノードD_n間の重要度 I_n (0〜1 の値) が入力として与えられる。



#+BEGIN_raddblock 
固定信頼度delta が入力として与えられる。

#+END_raddblock 

この時、ノードS〜ノードD_n のノードペアの中で、

K 個のノードペア (S, D_s_1), (S, D_s_2), ... (S, D_s_K) における忠実度が最大のリンクをそれぞれ発見する。

#+BEGIN_raddblock 
発見するリンクのノードペア数 K は入力として与えられる。
#+END_raddblock 

ここで F_n は (S, D_n) 間において忠実度の最大のリンクの忠実度である。


* なぜ変更したか

# - ノードS〜ノードD_n間の重要度 I_n (0〜1 の値) が入力として与えられる。

# #+BEGIN_raddblock 
# ノードS〜ノードD_n間の重要度 I_n (忠実度と同じ範囲から等間隔に選ばれた
# 値) が入力として与えられる。

# 例)
# 宛先数4、 忠実度が[0.7,1.0]をとるとき
# 重要度は 0.7, 0,8, 0.9, 1.0 に設定される。
# その後、各宛先に重複しないように割りあてられる。

# #+END_raddblock


# 忠実度と重要度を対等な重みで扱うため。忠実度が[0.7,1.0]のとき、重要度
# I_n (0〜1 の値) を入力として与えると、重要度と忠実度の積が重要度に大き
# く依存してしまうから。

#+BEGIN_raddblock 
- 固定信頼度delta が入力として与えられる。
#+END_raddblock 

#+BEGIN_rdelblock 
- 総バウンスコスト C が入力として与えられる。
#+END_rdelblock 


先行研究である、linkselfieの優秀なロジックを活かすことができるため。

#+BEGIN_raddblock 
- 発見するリンクのノードペア数 K は入力として与えられる。
#+END_raddblock 
#+BEGIN_rdelblock 
ただし、発見するリンクのノードペア数 K は、

重要度と忠実度の積の総和、つまり

I = \sum_{k = 1}^K I_s_k * F_s_k 

が最大となるように定める。
#+END_rdelblock 


重要度と忠実度の積は負にならないので、この変更前の設定だと

発見するリンクのノードペア数 K = 宛先ノードの数

になる。常に全ての宛先を選択することになり、複数の宛先間の重要度を考慮
する意味がなくなるため。



* 現在のテーマの問題点
上記の問題設定は、linkselfieのロジックを使いたいという私情が入っていた
り、もともと想定していた、"発見するリンクのノードペア数 K は、重要度と
忠実度の積の総和が最大となるように定める。"という問題設定が解くべき問
題にならなかったため、 K を事前に入力として与えるという梃入れがされて
いる。

一部の問題設定が実問題に沿った内容になっていないと考えられる。
